### 1. ✅ Use BuildConfig.VERSION_NAME instead of hardcoded version

**Reviewers:** Copilot, Codoki, CodeRabbit (all flagged this issue)

**Issue:** The client version was hardcoded as "1.1", which would become stale over time and not reflect actual app versions.

**Change Applied:**
```kotlin

clientInfo = ClientInfo(
    name = "CleverFerret",
    version = "1.1"  // ❌ Hardcoded
)

// After:

    name = "CleverFerret",
```

**Benefits:**
- ✅ Version automatically stays in sync with app version
- ✅ Server receives accurate client version for diagnostics

- ✅ Consistent with Android best practices

## Technical Details

### BuildConfig.VERSION_NAME

The `BuildConfig` class is automatically generated by the Android build system and contains:
- `VERSION_NAME`: The version name from `build.gradle.kts` (e.g., "1.1.0")
- `VERSION_CODE`: The version code as an integer
- `APPLICATION_ID`: The application package name
- Other build-time constants

Using `BuildConfig.VERSION_NAME` ensures that:
1. The Jellyfin server receives the actual app version
2. Server logs and diagnostics show correct client versions
3. Version changes during builds are automatically reflected
4. No manual version string updates needed in code

### httpClientOptions Configuration

The custom OkHttpClient is properly passed to the Jellyfin SDK via:
```kotlin
httpClientOptions {
    client = okHttpClient
}
```

This ensures all custom configuration is maintained:
- Custom timeouts
- Interceptors for logging/authentication
- Connection pooling settings
- SSL/TLS configuration
- Any other OkHttp customizations
